# 01 – Cursor als Referenz

## Was übernommen werden soll

Cursor dient als Referenz für:

- task-orientierte Navigation
- klare Zustände laufender Agentenarbeit
- reduzierte visuelle Hierarchie
- schnelle Wechsel zwischen Aufgaben
- Review als eigener Arbeitsschritt
- statusbasierte Organisation statt technischer Kategorien
- sekundäre technische Informationen
- kompakte, fokussierte Desktop-UX

## Was ausdrücklich nicht kopiert wird

- komplette IDE-Struktur
- Editor-first UX
- VS-Code-Seitenleisten
- umfangreiche Panel-Verschachtelung
- Multi-Agent-Grid ohne nachgewiesenen Nutzen
- exakte Cursor-Farben, Typografie oder Branding
- unnötige Projektmanagement-Komplexität

## Pi-Designprinzipien

### 1. Task first

Der aktuelle Task ist die wichtigste Einheit.

### 2. Activity statt Toolspam

Toolaufrufe werden nach semantischen Ereignissen gruppiert.

### 3. Status ist sichtbar, Technik ist sekundär

`Working`, `Needs Input`, `Review`, `Verified`, `Completed` sind wichtiger als Tokenzahl oder Context Window.

### 4. Progressive Disclosure

Details werden bei Bedarf geöffnet statt permanent angezeigt.

### 5. Review ist Teil des normalen Flows

Changes und Verification sind keine Nebenansichten.

### 6. Keine redundanten Informationen

Modell, Thinking und Workflow dürfen nicht mehrfach gleichzeitig erscheinen.

### 7. GUI ≠ TUI im Fenster

Die GUI nutzt Desktop-Fläche gezielt und führt neue Informationshierarchie ein.
